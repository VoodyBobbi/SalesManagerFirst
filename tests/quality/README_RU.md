# Контрактные тесты качества

Все автоматические тесты проекта находятся в `tests/`. Файлы в `tests/quality/` — дополнительные офлайн-проверки контрактов SQLite, поиска, GigaChat, почты, сохранения настроек и самой системы оценки. Они обнаруживаются обычным запуском из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Дополнительные зависимости не нужны: используется основной `requirements.txt` и настроенное окружение проекта.

## Повторная проверка качества

Из корня проекта:

```powershell
.\.venv\Scripts\python.exe tests/quality/runner.py --repeats 1
.\.venv\Scripts\python.exe tests/quality/runner.py --repeats 5
```

В этой папке также сохранены три CMD-файла для двойного щелчка. Они используют только `.venv` проекта и возвращают код ошибки при неуспехе. Если окружение другое, запускайте `runner.py` его полным путём к Python.

Runner повторяет только контрактные тесты `tests/quality`, а обычный `pytest` проверяет весь проект, включая интерфейс. Используется один корневой `pytest.ini`; отдельных конфигураций и второй копии тестов нет.

Результаты: `tests/quality/reports/latest.md`, `latest.json`, журналы `run_XX.log` и JUnit `run_XX.xml`. Это генерируемые локальные материалы, исключённые из Git.

## Эталон

`СОХРАНИТЬ_ЭТАЛОН.cmd` запускает пять прогонов и записывает `reports/baseline.json` только при полном успехе. Следующие проверки показывают ухудшения, исчезнувшие и новые сценарии, несовпадающее число повторов и неполные результаты. Не перезаписывайте эталон после каждой правки. После переноса из прежней папки изменились идентификаторы сценариев: старый отчёт нельзя молча считать эталоном новой структуры.

## Интерпретация

- `OK`: сценарий прошёл каждый прогон.
- `НЕСТАБИЛЕН`: были как успехи, так и провалы.
- `ОШИБКА`: успешных прогонов нет.
- `ПРОПУЩЕН` / `НЕПОЛНЫЙ`: часть испытаний не состоялась; это не успех.
- `pass@k`: был хотя бы один успех из k запусков; `pass^k`: успешны все k запусков.

## Изоляция и границы

Контрактные тесты используют синтетические данные, временные SQLite-базы, поддельные секреты и транспорт. Прямые подключения к сети запрещены фикстурой; пользовательская база, настоящие пароли, почта и API не используются. Самопроверки runner проверяют расчёт метрик и отказ от ложного успеха при старом XML, ошибке сбора или неполном эталоне. Они не запускают вложенный runner.

Успешные офлайн-тесты не подтверждают работоспособность реальных Gmail, GigaChat или поисковых сервисов и качество живых ответов модели.
