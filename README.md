# SALES MANAGER FIRST

Настольная программа для Windows: выбрать востребованный товар, найти возможных покупателей, подготовить УТП и отправить выбранному получателю после подтверждения.

Текущая версия — **1.4.3**. Для запуска нужен только `dist/SalesManagerFirst.exe`; Python и словари отдельно устанавливать не нужно. Для поиска, GigaChat и почты нужен интернет. EXE не подписан сертификатом издателя, поэтому Windows может показать предупреждение о неизвестном издателе.

## Как начать

1. Откройте `dist/SalesManagerFirst.exe`.
2. Во вкладке «Рынок» выберите страны и нажмите «Найти товары».
3. Посмотрите найденные товары, их показатели или признаки спроса. Кнопка «Источники» открывает подтверждения.
4. Нажмите название товара, чтобы открыть его компании. Свой товар можно ввести во вкладке «Компании» и подтвердить Enter.
5. Нажмите «Найти компании». Для одной известной организации используйте «Ещё» → «Добавить компанию по ссылке».
6. Откройте карточку компании двойным щелчком, проверьте факты и применимость. Для спорного кандидата доступна оценка GigaChat или ручной статус с причиной. Ручное решение сохраняется и не заменяется ИИ автоматически.
7. Укажите подтверждённое основание для контакта. Откройте «УТП», выберите актуальный email, проверьте текст и явно подтвердите отправку.

Для подготовки УТП подключите GigaChat в «Настройках», для отправки и ответов — почту. Поддерживаются Gmail, Яндекс и ручные IMAP/SMTP. Используйте отдельный пароль приложения. Для Gmail стандартные серверы: `imap.gmail.com:993`, `smtp.gmail.com:465`; для ручного SMTP также поддерживается 587 с STARTTLS. Основной пароль ящика не требуется. УТП формируется из сохранённых страниц компании; страницы могут кэшироваться до 24 часов. Перед важным предложением обновите исследование компании и проверьте цитаты и источники в карточке.

## Что показывает «Рынок»

Результат — до **10 разных видов товаров** с подтверждениями для выбранных стран. Бренды смартфонов объединяются; пылесос Xiaomi не становится смартфоном. Случайные упоминания и вымышленные объёмы для заполнения десятки не добавляются.

Сравнимые показатели продаж, закупок, заказов и поисковых запросов показываются отдельно по единицам, странам и периодам. Если сопоставимых измерений нет, отображается предварительная оценка по независимым публикациям и их свежести. Прочерк не подменяет доступное объяснение спроса: основание видно в таблице. Процент относительно лидера используется только для сопоставимых показателей, а не как доля рынка.

Вверху показан один короткий итог: сколько товаров найдено и сколько поисковых инструментов действительно ответило. Знаменатель определяется реестром поддерживаемых источников рынка; сейчас это восемь: Tavily, Serper, Exa, Firecrawl, Jina Search, GDELT, RSS и публичные публикации закупок. Один инструмент считается один раз, независимо от числа запросов или RSS-лент. В строке товара «Источники» означает число подтверждающих страниц, а не количество поисковых инструментов.

Поиск выполняет сохранённый план самостоятельно: распределяет запросы между доступными источниками, объединяет выдачу и проверяет страницы. Успешные запросы, включая пустую выдачу, кэшируются; сбой одного источника не останавливает остальные. Размер пакета ограничивает обработку за один этап, после которого программа продолжает автоматически. Если найдено меньше десяти товаров, выполняются дополнительные запросы по недостаточно представленным категориям, когда для них доступны подходящие источники. Товары для заполнения списка не придумываются.

Во время длительной операции в центре окна появляется полупрозрачная плашка с текущим этапом. Повторный запуск и конфликтующие действия временно заблокированы. Фоновая проверка почты плашку не показывает. После выполнения доступного плана выводится окончательный итог с фактическим количеством товаров и ответивших поисковых инструментов. При закрытии приложения незавершённая работа сохраняется и автоматически восстанавливается при следующем запуске; прерывание не считается успешным завершением. Технические причины отказов находятся в диагностике SQLite.

UN Comtrade сохранён как отдельный адаптер и архив ранее собранного импорта. В обычном поиске рынка он не вызывается, кнопки импорта нет. Overpass, Wikidata, MediaWiki и каталоги компаний используются для других задач и не входят в знаменатель первоначального поиска товаров.

## Подключение поисковых API

В «Настройках» выберите источник, введите ключ, включите «Использовать» и нажмите «Проверить». Действительность ключа и возможность бесплатного поиска проверяются отдельно. Галочка пользователя или положительный остаток сами по себе не подтверждают отсутствие списаний.

Для Tavily поддержан документированный бесплатный профиль **Researcher** при отключённом Pay-as-you-go и достаточной квоте. Перед поисковыми запросами ограничения перепроверяются; при исчерпании квоты поиск переходит к другим источникам. Устаревшее подтверждение обновляется безопасным запросом сведений об аккаунте.

Для Exa, Serper, Jina и Firecrawl с ключом опубликованных данных недостаточно, чтобы подтвердить бесплатность и запрет автосписаний; такие подключения остаются отключёнными с конкретным объяснением в настройках. Firecrawl без ключа доступен только если сервис разрешает запросы с вашего IP. Открытые RSS, GDELT и настроенные публичные публикации продолжают работать независимо от ключей.

RSS по умолчанию включает одиннадцать отраслевых и деловых лент, в том числе публикации компаний Retail.ru, технологии и автомобильный рынок «Ведомостей». Это опубликованные издателями интерфейсы агрегации: [Retail.ru](https://www.retail.ru/rss/), [Ведомости](https://www.vedomosti.ru/info/rss). Можно указать собственные разрешённые RSS и публичные страницы закупок; за исследование читается не более 16 уникальных лент. CAPTCHA, авторизация и robots.txt не обходятся. Сбой отдельного источника не останавливает обработку остальных.

## Данные и безопасность

Пользовательская база: `%LOCALAPPDATA%\Argon\SalesManagerFirst\sales.sqlite3`. Схема обновляется до версии 6 последовательными атомарными миграциями; старые таблицы, импорт, переписка и разрешения сохраняются. Пароли и ключи хранятся в Windows Credential Manager (`Argon.SalesManagerFirst`), с привязкой к текущей учётной записи и компьютеру. В EXE входят только код и публичные ресурсы приложения, без пользовательской базы и ключей. Перенос EXE не переносит чужие учётные данные. Локальное защищённое хранилище не защищает от вредоносного ПО, уже получившего доступ к учётной записи Windows.

Если Windows не позволяет ограничить хранение старого ключа этим компьютером, программа сохраняет доступ к данным и показывает предупреждение в настройках. Новые ключи сохраняются локально.

Программа не отправляет письма автоматически. Для отправки нужны FIT, актуальный выбранный email, основание и подтверждение контакта, отсутствие запрета и явное подтверждение письма. FIT означает соответствие компании найденным сведениям о деятельности, а не подтверждённое намерение или текущую потребность купить. Основание контакта и подтверждение вводит пользователь; приложение проверяет заполнение и почтовые ограничения, но не подлинность самого подтверждения. При неизвестном результате SMTP повторная отправка автоматически не выполняется. Отправленное письмо доступно для просмотра; его текст и адресат защищены от изменения. Исчезнувший email нельзя незаметно заменить другим адресатом. Ручное решение «Подходит» не отменяет почтовые проверки.

Для GigaChat достаточно ввести ключ авторизации, выбрать параметры своего доступа и нажать «Проверить». Защищённое HTTPS-соединение настраивается автоматически, проверка подлинности сервера включена. Словарь русских словоформ включён в EXE.

## Разработка и проверка

Используется Python 3.12 x64; зависимости закреплены в `requirements.txt`. В PyCharm перед Python-командами нужно получать настроенный SDK через `get_python_environment`.

```powershell
.\.venv\Scripts\python.exe main.py
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe tests/quality/runner.py --repeats 5
powershell -NoProfile -ExecutionPolicy Bypass -File packaging\build.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File packaging\verify-exe.ps1
```

Все результаты тестов и сборки находятся внутри `build/`. Явная живая проверка без личных ключей и рабочей базы: `.venv\Scripts\python.exe packaging/check_market_release.py`; её результаты и отдельная SQLite — в `build/live-market-release/`. Это не часть pytest. Подробный отчёт выпуска и границы проверки — в `TEST_REPORT.md`.

## Карточки компаний и границы результатов

Кандидаты со статусом «Нужна проверка» остаются в списке, даже если сайт не дал контактных данных. Такой статус не подтверждает соответствие товара. Предложение доступно только для подтверждённых FIT карточек.

Контакт можно добавить вручную вместе с публичной ссылкой на источник. Ссылка сохраняется как источник, указанный пользователем; программа не подтверждает её подлинность и не считает её разрешением на рассылку. Основание и подтверждение разрешения на контакт по-прежнему вводятся отдельно.

Оценка рынка зависит от доступных публикаций и поисковых источников: программа может вернуть меньше десяти товаров. Это ориентир по найденным сведениям, а не точная оценка объёма рынка.
